**R-VIS-01 overall: BLOCKED** for public reasoning delivery; the exact absence and honest UI are demonstrated. This is distinct from a provider failing to emit reasoning on a specific turn, and distinct from a supported public event that TORI simply failed to render. The earlier [provider observation repair](REASONING-VISIBILITY.md) is historical evidence, not a public VICT pass. This candidate removes that provider-only UI projection. It preserves historical records and identifies earlier observations as outside the public VICT contract. A validated public `text.delta` can drive writing-answer state, never Thinking. Private reasoning is stripped before product Mastra, and unexpected non-streaming response formats fail closed.

## Smallest upstream change for separate authorization

Add an opt-in, versioned VICT companion contract (for example `vict.agent-reasoning@1`) keyed to the existing VICT stream, turn and activation identities. Leave strict v1 parsing unchanged. First support content-free lifecycle markers: observed start and ended, with explicit completion/interruption semantics. The Mastra adapter should map actual reasoning lifecycle observations only, with no raw deltas. The hub should enforce ordering, scope and one terminal state and preserve safe markers across replay. Enable a separate summary event only for an explicitly provider-designated, shareable summary; carry a bounded authorized reference and source, never rebrand reasoning deltas as a summary. TORI would display real activity and use a public VICT disclosure control for a real summary. Extending the profile to pin provider reasoning effort is a separate generation-contract change and is not a dependency for this visibility extension.

Upstream proof must exercise an installed fixture with observed reasoning, missing reasoning, explicit public summary and private-text canaries. Test v1 compatibility, opt-in, correlation, interrupted turns, replay/deduplication, denied summary access, and no raw payload in traces, storage, DTOs or consumer UI. Repeat with an owner-permitted live model and compare adapter, hub, and consumer receipts before changing the R-VIS-01 verdict. No upstream work has been authorized or performed here.

## Reproduce

Use the installed, locked dependencies and Node 24.15.0. `node scripts/probe-reasoning.mjs` performs the deterministic boundary probe, reporting event kinds only. For the separately approved Z.AI test route, run with `--live` and a server-process `TORI_ZAI_API_KEY`; optionally add `--effort=low` to test request acceptance. The live diagnostic uses a standalone Mastra Agent with no memory or telemetry export. It is a verification harness, not a Studio runtime or private event API. `npm test` passed four tests; `npm run build` passed with the existing chunk size warning. Older V1a acceptance evidence remains separately attributed.
