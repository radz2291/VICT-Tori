# Final Studio public-control and accessibility audit

This audit supersedes the historical R2 [control inventory](../../VICT-CONTROL-AUDIT.md) for TORI-002. It covers the five presented pages and all reachable shell, dock, menu, picker, editing, feedback and confirmation roles in this candidate. The [verification record](README.md) identifies the exact product, served bundle and independent verifier.

All VICT packages below are installed public tarballs at `0.4.0-rc.1`, from the [G0 dependency proof](../../../g0/DEPENDENCIES.md). Manifest export paths and actual source imports were inspected independently. No UI exception is used.

Source sweep found no app-authored native button, input, select, textarea or dialog replacement. Semantic layout, headings and lists compose public controls.

The rendered audit `scripts/audit-studio-ui.mjs` opens all five pages, every shell menu family, Workflow Select, dirty-reopen confirmation and phone Inspector. It records [computed focus and text contrast](audit.json), plus desktop and phone screenshots. The focused text field has a 3px accent outline with 3px offset. The graph node wrapper has its own visible focus outline with 4px offset, distinct from selection on the inner node. Measured native edge stroke is rgb(170,170,176), 2px wide, exceeding 7:1 against the graphite canvas. Port labels use the shared foreground and visible endpoints use the shared accent. Measured normal text contrast ratios range from 7.04 to 15.44 for the sampled field, heading and muted readiness surfaces. Shared accent is above 6:1 on graphite surfaces. Disabled controls retain native disabled semantics.

Reduced-motion Chrome contexts, 390px touch/mobile emulation, 640px keyboard authoring and a 200% CSS layout enlargement were exercised. Desktop and narrow panel tests also check document overflow and the anchored navigator. Screen-reader hardware, an actual touch device and OS/browser-specific magnifier behavior remain untested. Those limits are separate from the executed DOM semantics, keyboard, pointer, focus and layout checks.

This candidate offers explicit Fit, Zoom and Reveal across authoring pages. Deliberate camera positions remain stable through ordinary panel and page changes. Changing viewport size can retain an offscreen camera position until the operator invokes those controls. Fresh phone Creative starts with a readable object.
