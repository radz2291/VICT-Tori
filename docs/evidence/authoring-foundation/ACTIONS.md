## Trust and execution

The persisted authoring activation is created in Configure by binding **Draft Authoring → Workspace authoring · r1**, selecting four model steps, saving and activating. The existing instruction-only revision remains available. Each workspace turn starts with **Review only** selected. Review exposes the inspection tool to the provider and the VICT invocation gate enforces the same read-only authority. **Allow edits and tests** grants the requested local operations for one turn. Studio binds ordinary edits to the open draft from the trusted turn context. An explicit reference is checked against that same draft. Model inputs contain authored values and resource references. Actor, grants, provider, workspace, subprocess and approval configuration are host-owned.

The browser owns edits on the selected draft and recovers its VICT receipt and journal action together. Creation and test reservation use the local SQLite project transaction. An attached Save accepts the same revision-checked graph snapshot as manual Save. A Save-only action reserves the canonical saved revision without adding an Undo entry. A Stop before the browser journal commits prevents the edit. An edit committed before Stop remains undoable. An attached Save has its own server fence and reports its outcome alongside the edit. Browser retry reuses the original workspace turn or draft receipt identity.

The saved-specialist capability `tori.delegate.saved-agent@1` pins the child and returns its actual text and Run ID under the child's configured output-token limit. The earlier offline capability and its immutable activations retain their contract. Each parent turn admits one child execution. VICT reconciles the same logical invocation. The host reserves the pinned budget before dispatch, including parallel requests. An additional request receives a refusal and a registered-script overflow records zero process spawns.

The local adapter runs `process.execPath` with a trusted module entry and one validated synthetic key. The child process receives an empty environment and closed stdin. There is no shell invocation. The registry fixes the path, version, read grant and allowed keys. The request is checked before dispatch and the script checks its own key against its synthetic data. Timeout is five seconds, cancellation kills the process and stdout is capped at 2,048 bytes before parsing the typed result. Each receipt records whether a process spawned.
