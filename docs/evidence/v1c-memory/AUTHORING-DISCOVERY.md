# TORI-006 Authoring discovery regression

Product `d49bedf362d3521bcbf714bc6be7a04b34289bb7` (tree `ecb81c26521caa48f7435a6ecf43bc3426579c23`) on `codex/tori-v1c-memory-foundation`. It follows the [typography delivery](TYPOGRAPHY.md) at `e4fdcc8986633c9e141cb8f80cbb5c73c2a3e4ee`. The previous owner preview ran `15806e7d7377283650715067163ecb75dce3a4ef`.

## What broke

The graph resolver began returning `savedMemory` for a bound Memory Policy in the Memory Foundation. The owner repair added `organizer`, which resolves to `off` even when there is no Memory Policy node. The workspace inspection tool spread the resolver's full object into its existing strict `workspace@1` result, both for the open draft and for a specifically requested saved definition. VICT rejected the result before it reached the model. The browser fixture then tried to read `contextSources` and `tools` from the failure payload; its undefined-property error was a downstream symptom.

With a live provider a turn can still be recorded as completed: on the old preview product the Run contained `tool.failed`, the provider received only `victCapabilityFailure`, and the assistant could not report the actual draft or tools. Workflows that rely on discovery to build, edit or review in Authoring could be blocked or proceed without those facts. Ordinary chat and the direct memory card use different paths.

The host now projects only the fields declared in the existing Authoring discovery result. Memory policy state is still resolved by Studio; Authoring's strict result contract, permissions and provider fixture are unchanged. A permanent regression covers discovery of both the open draft and an explicitly named saved definition with Governed Memory configured. It failed before the repair and passed after.
