## 2. Detail levels and working groups

- **Quiet:** final answer; one unobtrusive collapsed activity group when there is actual activity. Failures, denials, limit hits, interruption and uncertainty always surface, at least through a visible badge and inspect action. Quiet never hides a problem.
- **Summary:** final answer plus factual activity chips, such as sources admitted/read, delegation and observed step count.
- **Full trace:** all retained, authorized public operational evidence: steps, safe tool calls/results, question/answer exchanges, timings, applied limits and terminal reason. Missing or pruned content is explicit. This is not private reasoning or raw provider metadata.

The preference changes only projection. All levels use the same authorized receipts and existing retention/redaction rules; no extra model/tool call, new Run, retention change or event deletion occurs when switching.

Group consecutive non-final activity into stable, collapsible phases derived from actual events. Activity after an answer boundary, when the original authorized Run genuinely continues, gets a separate **Continued working** group. It never merges into or rewrites the answer, and this view introduces no automatic post-final work. A final answer is not by itself proof that all children/effects finished.

Use the existing four outcomes — Finished, Running, Interrupted, Uncertain — with the authoritative terminal reason and effect certainty. A stream disconnect is a delivery diagnostic, not proof of interruption. Compose installed public VICT Accordion/Disclosure, badges and other controls; inspect the actual exported role before use. New primitives require the existing UI-exceptions process. Preserve keyboard operation, reading order, focus and narrow-screen behavior.

## 4. Synchronous child-to-parent questions

Probe whether the pinned public delegation/Mastra path can return a typed question, run the parent's answer step and continue the original governed child occurrence with its pinned scope, accumulated budgets and receipts. Do not assume suspend/resume or signals work because the UI can show a waiting label. If a supported continuation cannot preserve these invariants, stop that criterion with exact evidence and continue independent display work.

A question and answer are information, never permission. The host validates originating child/parent/invocation, activation, operation identity, current authorization and exchange count. Record the exact safe public question/answer and their receipt links. A duplicate question or acknowledgement cannot dispatch an extra parent step or child effect. Refuse orphan, wrong-parent, stale, revoked and late-terminal responses.

Charge parent answer steps and any dispatches to the existing parent execution policy; charge child steps/tools/retries to its pinned policy. Asking never resets a child's counters or bypasses the original Run deadline. Time spent waiting remains inside the existing deadlines. An exhausted budget produces an explicit reason; a model cannot ask for permission through a data answer.

Parent Stop/deadline cancels its pending exchange and linked child. Cancellation of the child propagates to the outstanding parent wait/answer work for that invocation; no child continuation follows. Settle the enclosing parent truthfully under the installed failure policy, without canceling unrelated Sessions/Runs. Probe both directions and both sides of the completion race. Crash/restart preserves the Background Foundation Interrupted/Uncertain behavior; no auto-replay/resume is added.

A timeline row may render “Asked parent: … · Answered: …”, with actual receipts and an explicit unanswered outcome when applicable. Every exchange remains under the existing data trust hierarchy and actor/project/agent boundaries. No automatic delegation-depth increase, recursive parent/child network, extra child activation or scope widening.
