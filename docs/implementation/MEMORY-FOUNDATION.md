## Outcome

You can tell Quellight, “Remember that I prefer project updates in three short bullets.” It confirms the saved preference. After restarting Studio and opening a fresh Session, you can ask for a project update and inspect the saved preference admitted to that Run. You can correct the preference to two bullets or forget it and verify the effect in another Session.

Compose the existing Memory Policy controls and Run details with installed public VICT controls. The activation pins two independently configured settings: its 10- or 100-message Session history window and its opt-in saved-memory policy. Existing activations resolve saved-memory access as off. Read and write authority is evaluated at runtime so revocation or deletion takes effect on later turns using an older activation. [Current scoped memory](https://github.com/radz2291/VICT-Tori/blob/4c035cd75f63c68bd002dee5683ca3fa02e778cf/docs/evidence/v1a/A3.md)

## Four implementation decisions

1. **Explicit records and bounded recall.** Store saved memories and their revisions in dedicated local SQLite tables. At turn start, select active records in the trusted scope, order by latest change with a stable tie-breaker, and admit them within a declared per-turn memory context budget. Document and test the bound using the existing context-admission conventions. Attach the selected values as a distinct context block. Keep `semanticRecall:false`. Reuse the pre-dispatch admission and receipt pattern from `loadContext`, whose current implementation reads an explicitly requested, pinned fixture source. Give saved memory its own policy, loader and receipt so source reads and memory reads are independently inspectable. Treat admitted text as user data under the existing instruction and authority hierarchy. [Current admission code](https://github.com/radz2291/VICT-Tori/blob/4c035cd75f63c68bd002dee5683ca3fa02e778cf/server/a3-runtime.mjs)
2. **Governed save.** Use a versioned `tori.memory.save` capability with a turn-bound grant, trusted scope, idempotency key and receipt. For the first live path, the host recognizes the explicit `Remember that …` form in the current operator message, binds the submitted value and scope, and grants that save for that turn if the policy permits it. Ordinary messages continue through chat. History, tool output, retrieved text and model claims cannot create the grant or change its bound value or target. Use the installed VICT capability gate and the current cancellation and receipt conventions. Commit the record and operation receipt in one transaction. Recheck scope and authority on replay. The same operation and payload return the original receipt; a conflicting payload is refused. A replay of a save for a forgotten record leaves the tombstone in place. Stop or expiry before commit leaves no memory. A committed save remains discoverable if the reply is interrupted. Confirm a save only from its committed receipt. [Existing capability and idempotency pattern](https://github.com/radz2291/VICT-Tori/blob/4c035cd75f63c68bd002dee5683ca3fa02e778cf/docs/evidence/authoring-foundation/ACTIONS.md)
3. **Trusted scope and isolation fixtures.** Key memory by actor, project and stable agent definition ID. A fresh Session or new activation of that definition can use the same store when authorized. Child agents resolve their own scope. Local Studio keeps its current single-operator identity. Add a trusted server-side fixture path for a second actor and a second project. Exercise both against the same memory store, changing one scope field at a time while keeping the saved record present. Verify that reads, inspection, correction, deletion and writes are denied or empty as appropriate. Also test another agent in the same project. Request-body and model-supplied identity fields cannot select a different scope. [Current Studio host](https://github.com/radz2291/VICT-Tori/blob/4c035cd75f63c68bd002dee5683ca3fa02e778cf/server/studio.mjs)
4. **Revision and deletion.** Each memory has a stable ID and revisions. A revision records scope, content, source Session/message reference, saving turn/Run and creation time. An authorized correction against the current revision creates a successor and supersedes the prior revision atomically. Reject stale edits. Keep superseded versions for provenance while the record exists. Forgetting removes the content of all revisions and any memory-derived copies under TORI's control from future retrieval and memory inspection. Retain a content-free tombstone and receipt references for reconciliation and historical Run audit. Existing Session messages, including replies composed with admitted memory, follow Session retention. The forget action removes the reusable memory entry. Saved records persist until corrected or forgotten in this slice. Use authorized, revision-aware Studio actions for inspect, correct and forget.

## Run evidence

Record memory admission for each in-scope Run, including **0 memories admitted**. Show the reason when applicable, such as policy off, no eligible memories, budget omission or storage unavailable. For admitted records, show the memory ID, revision and source reference. Resolve viewable content from the authorized store, and display a forgotten record as such in older Runs. Keep memory text out of the receipt itself. A receipt proves the input supplied to a Run. The walkthrough checks whether the response follows that input.

## Acceptance

D is deterministic verification, S is a real Studio browser walkthrough, and L is a permitted live-model walkthrough. Use one synthetic preference in an otherwise empty memory scope for the live sequence. Ask for an update without restating the preference. Keep source, package, fixture and candidate pins in the evidence.

| Criterion | Evidence | Pass condition |
|---|---|---|
| Explicit save and restart recall | D/S/L | Enable the policy, save the three-bullet preference, restart Studio and start a fresh Session. Record the committed save, admitted memory revision and live response using the preference. A history-only control shows zero admitted saved memories. |
| Governed, repeatable writes | D/S | Ordinary chat and a tool or model attempt to fabricate a grant produce zero writes. Stop before commit produces zero writes. Retrying after a lost acknowledgement returns the original receipt and one record. |
| Trusted isolation | D | The actor, project and agent fixtures share the same store. Each independently proves zero cross-scope admissions and zero unauthorized mutations. An authorized control reads the seeded record. |
| Correct and forget | D/S/L | Correct three bullets to two, then show only the current revision in a fresh Run. Forget the preference and prove zero admissions on a fresh turn and after restart. Verify superseded content is gone from the memory store and the older Run retains content-free audit evidence. |
| History and UI | D/S | Existing 10/100-message behavior and chat continuity pass regression checks. Desktop and narrow Studio display the same policy, saved-memory controls and Run evidence, including the zero state. |

This covers part of CAP-16 and X09, the applicable X04 scope checks, and a bounded contribution to T01-06. Run the existing build and relevant regression tests, then have an independent verifier challenge the exact candidate. **Stop conditions.** If the installed VICT boundary cannot support the required grant, cancellation or receipt, identify the exact missing interface and affected test. A scope leak or an unverified deletion blocks acceptance. Missing live provider access holds the live proof while deterministic and Studio work can proceed.

## Proposed decision register entry

V1c is a multi-slice stage. Begin with explicit saved memory, then advance background execution and recovery, then specialist Run visibility and controls. Give opt-in observational memory its own proof with source evidence from multiple ordinary conversations. Semantic retrieval requires the planned exact-version Mastra conformance probe. The broader memory acceptance includes retention and export coverage. Existing real-world acceptance scenarios remain cumulative.
